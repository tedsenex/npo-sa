# 七個模組｜功能清單

**建立日期：2026-08-06**

> 這份只談工具本身：每個模組實際有哪些功能、使用者在畫面上能做什麼。
> 分層與依賴見 [`functional-architecture.md`](./functional-architecture.md)，這份是它 §3 的展開。

---

## 0. 先講一件會影響工作量的事

CLAUDE.md 說「其餘六個模組都是複製 M3 的形狀」。**實際上只有三個是。**

七個模組其實有四種形狀：

| 形狀 | 模組 | 特徵 |
|---|---|---|
| **生成型** | M3 · M4 · M5 · M7 | 選類型 → 填真材料 → 生成 → 守門 → 編輯 → 存／排程 |
| **診斷型** | M1 | 問卷 → 計分 → 缺口排序 → 報告 |
| **規劃型** | M2 | 輸入條件 → 結構化計畫 → **長期追蹤與回看** |
| **資料型** | M6 | 拉外部數據 → 檢核 → 呈現（不生成） |

生成型那四個確實是複製 M3。但 M1、M2、M6 各是一套新東西——
**M2 尤其是**，它不是一次性產出，是一份會被反覆回來修改的活文件，資料模型與畫面都跟生成型不同。

排期時要知道：M3 做完不等於六個模組都只剩複製貼上。

## 1. 生成型模組的共用形狀

M3 · M4 · M5 · M7 共用這一套流程與畫面。**做 M3 時就要把它抽成共用元件。**

### 流程

```
① 選類型          七型／角度／六型／敘事模板
② 填真材料        seed、素材、條件         ← 空的就擋，不呼叫 LLM
③ 生成前檢查      額度、配額、必填         ← 不過就回 400／409
④ 生成            組 context → LLM
⑤ 守門            guardrail pipeline
⑥ 看報告          通過幾關、被改了什麼
⑦ 編輯／重生成／微調
⑧ 存檔            寫進各自的產出表
⑨ 排程／匯出
```

### 共用畫面元件

| 元件 | 說明 |
|---|---|
| **類型選擇器** | 卡片式，每型附一句說明、適用情境、**一則範例產出** |
| **真材料輸入框** | 附提示問句與範例。這欄空的按鈕就是 disabled |
| **額度條** | 本月已用／總額，接近上限時變色 |
| **生成按鈕** | 按下即鎖定（防連點重複扣費） |
| **守門報告面板** | 逐關顯示通過／警告／擋下，被改的地方要能對照原文 |
| **產出編輯器** | 可改。**改完存檔要重跑守門** |
| **重新生成 / 微調** | 微調要能帶指令（「語氣軟一點」） |
| **版本切換** | 同一次嘗試的多個版本可比較 |
| **狀態列** | draft / 待審 / 已核准 / 已排程 / 已發布 |

### 共用邏輯

- 生成前：驗 Zod schema → 檢查必填真材料 → 檢查額度與配額
- 生成後：**只要 LLM 被呼叫過就一定寫 `generations`**（含成本），不論守門結果
- 守門 block 時：回 200 + 遮蔽後的文字 + 完整報告，產出只能停在 draft
- 守門的 LLM 呼叫失敗時：**視為未通過，不放行**

## 2. M-1 協會腦（不是模組，是所有模組的資料入口）

五個分頁，每頁一套 CRUD。

| 分頁 | 功能 |
|---|---|
| **組織身分** | 全名、簡稱、立案字號、主管機關、slug。**只有 owner 能改** |
| **勸募許可** | 多張許可的新增／編輯；效期、核准用途、目標金額；**到期前提醒**。只有 owner 能改 |
| **事實庫** | key／value／出處／查核日／啟用開關；搜尋與篩選；**批次匯入 JSON**（顧問建檔後灌進來）；停用不刪除 |
| **紅線** | 規則描述、比對關鍵字或正則、嚴重度（block／warn）、啟用開關 |
| **品牌語氣** | tone 描述、禁用詞清單、3～5 則範例貼文、主色／輔色、logo、圖庫連結 |

**橫跨五頁的功能**：協會腦完成度指示（填了幾成），未完成時在各模組頁面顯示提醒。

> 事實庫是空的，所有模組的產出都會是一堆 `【請補資料】`。
> 完成度指示不是裝飾，是防止使用者在協會腦沒建好時就去生成然後覺得工具很爛。

## 3. M0 合規守門（橫切，不是獨立頁面）

守門本身沒有畫面，但有三個地方要露出：

1. **產出旁的守門報告面板**（每個生成型模組都有）
2. **產出歷史裡可回看每次的完整報告**
3. **設定裡的字典維護**：大陸用語對照表可新增詞條，三種處置：
   - `auto` 自動改（視頻→影片）
   - `warn` 只提示不改（優化→最佳化，技術語境可保留）
   - `block` 直接擋

十一關檢查的清單見 [`functional-architecture.md`](./functional-architecture.md) §L3。

## 4. M1 行銷健診

**形狀**：診斷型。**Phase**：P2。

| # | 功能 | 說明 |
|---|---|---|
| 1 | **逆向偵察** | 輸入協會名稱或官網 URL，自動抓公開資料：官網、社群佈局、捐款頁設計、第三方公益平台（iGiving／Backme／嘖嘖）使用情況、Google Ad Grant 跡象、人力規模 |
| 2 | **問卷填答** | 約 20 題，分曝光／認同／捐款率三段；可存草稿續填 |
| 3 | **三段計分** | 曝光、認同、捐款率各自的分數與級距 |
| 4 | **缺口排序** | 依影響程度排出問題清單 |
| 5 | **前三優先動作** | 具體、可執行、有先後 |
| 6 | **十二拍檢核** | 借 M7 的敘事結構當檢核表：協會現有的募款頁缺了哪幾拍 |
| 7 | **報告產出** | 可下載、可分享連結 |
| 8 | **雙導流 CTA** | 「缺口交給我們每天顧」／「用工具自己顧」 |

**畫面**：健診入口 → 問卷（分段進度）→ 報告頁

## 5. M2 年度募款規劃

**形狀**：規劃型。**Phase**：P3。**七個模組裡最不像其他人的一個。**

| # | 功能 | 說明 |
|---|---|---|
| 1 | **條件輸入** | 年度目標金額、現有管道現況、人力、既有檔期 |
| 2 | **分月拆解** | 依捐款季節性分配，**不是平均分**；每月數字可手動覆寫 |
| 3 | **四大檔期配置** | 春節前／年中／**年底抵稅（最重）**／週年或議題日 |
| 4 | **管道佔比** | 定期定額／單次／企業／義賣，各自的目標與佔比 |
| 5 | **掛勸募許可** | 每個檔期指定用哪張字號；**字號效期不涵蓋檔期時要警告** |
| 6 | **月度執行清單** | 每月要做的事，可勾選完成 |
| 7 | **風險提示** | 目標過於集中、人力不足、字號將到期等 |
| 8 | **進度追蹤** | 目標 vs 實際募得，分月與分管道 |
| 9 | **季度檢視模式** | 回來看達成率、記錄調整決議、留下修改軌跡 |

**畫面**：規劃精靈（多步驟）→ 計畫總覽（年曆／甘特）→ 檔期詳情 → 季檢頁

**跟生成型最大的差別**：這是一份**活文件**，會被反覆回來改，需要版本與修改軌跡。
生成型模組的產出是一次性的，這個不是。

## 6. M3 社群內容排程 ★ P1 唯一模組

**形狀**：生成型（本尊）。**Phase**：P1。

### 生成

| # | 功能 | 說明 |
|---|---|---|
| 1 | **選 archetype** | 七型卡片，每型附說明、引擎、適用情境、一則範例 |
| 2 | **選 platform** | Threads／FB／IG |
| 3 | **填 seed** ★ | 「今天實際發生了什麼真事」。**空的就擋，不呼叫 LLM**。附提示問句：這週誰來了／發生什麼／誰說了什麼 |
| 4 | **A4 週配額** | A4 每週上限 1，已滿時該型不可選並顯示剩餘天數 |
| 5 | **生成** | 帶入協會腦五區塊 |
| 6 | **守門報告** | 逐關顯示；被 G1 遮掉的數字要標出來讓人知道該補什麼 |
| 7 | **編輯** | 可改；改完存檔重跑守門 |
| 8 | **重新生成／微調** | 微調可帶指令 |
| 9 | **存成 content_item** | 進內容庫 |

七型：

| 代號 | 名稱 | 引擎 | 限制 |
|---|---|---|---|
| A1 | 導流長文＋輪播 | 換名單 | |
| A2 | 圖一句迷因 | 低成本拉新 | |
| A3 | 大字二選一 | 逼留言 | |
| A4 | 工具單 listicle | 乾貨 | **每週上限 1** |
| A5 | 素樸實作碎念 | 養信任 | AI 味最低 |
| A6 | 五步驟＋重複節奏 | 講方法 | |
| A7 | 認知反轉大字 | 蹭常識 | |

**禁用句型**：「不是 X 而是 Y」在 A4 以外全部禁止。

### 排程與發布

| # | 功能 |
|---|---|
| 10 | **內容日曆**：週／月視圖，看得到哪天要發什麼、哪天是空的 |
| 11 | **排程**：指定發布時間 |
| 12 | **審核狀態流轉**：draft → 待審 → 已核准 → 已排程 → 已發布 |
| 13 | **推送 Metricool** |
| 14 | **發布結果回填**：貼文網址、發布成功與否 |
| 15 | **內容去重**：生成時帶入近期產出摘要，避免每週寫同樣的東西 |
| 16 | **出圖**：接 `npo-social-card`（配色要吃 `org_voice`） |

## 10. M7 募款銷售頁

**形狀**：生成型（但一次生 12 個區塊）。**Phase**：P4。

| # | 功能 | 說明 |
|---|---|---|
| 1 | **選敘事模板** | 十二拍（完整）／八拍（精簡）／六拍（活動型） |
| 2 | **區塊化編輯器** | 12 種 block type，可增刪排序 |
| 3 | **逐區塊生成文案** | 每個 block type 一個 prompt；**LLM 只生 JSON 不生 HTML** |
| 4 | **設計 token** | 主色／輔色從 `org_voice` 帶入 |
| 5 | **圖片佔位** | 未填欄位自動渲染佔位框（編號、比例、圖示、名稱、說明） |
| 6 | **待補圖清單** | 側欄列出所有待補圖，可交給攝影師 |
| 7 | **進度條三模式** | `manual`（手填＋顯示更新日）／`api`（串金流）／`milestone`（只顯示里程碑）。**禁止自動遞增** |
| 8 | **沙箱預覽** | iframe 內預覽 |
| 9 | **匯出** | **單一 HTML 片段**（`<style>` + `<div id="brt-root">` + `<script>`），可直接貼進 1shop |
| 10 | **方案區設定** | `findPlansSection()` 的 id 清單與關鍵字清單可編輯 |

12 種區塊：`hero` · `quote_band` · `panel` · `narrative` · `icon_rows` · `typewriter` ·
`explainer` · `wall_cards` · `progress` · `service_cards` · `testimony` · `runners`／`allocation`／`equation`

**三個不可省的欄位**：困境卡的 `myth`（破除迷思）、證言的 `consent_note`（授權聲明）、
manual 進度條的 `updated_at`。

## 11. 跨模組的共用功能

不屬於任何一個模組，但每個模組都會用到：

| 功能 | 說明 |
|---|---|
| **產出歷史** | 列出所有 `generations`：模組、輸入、輸出、守門報告、模型、成本 |
| **成本看板** | 本月花費、分模組拆解、額度剩餘 |
| **成本上限** | org 級與全站級 hard cap，超過就停止生成 |
| **內容庫搜尋** | 跨模組找過去的產出 |
| **匯出** | 產出可匯出成文件交給協會 |
| **協會切換器** | 顧問與跨分會的 owner 會屬於多個 org |
| **稽核軌跡** | 誰改了事實庫、誰改了紅線、誰把產出改成已發布 |
| **通知** | 勸募字號將到期、事實庫該更新、額度將用完、排程發布失敗 |

**P1 的實際功能範圍**：M-1 五分頁 ＋ M0 的 G1/G5 ＋ M3 的生成那 9 項 ＋ 產出歷史 ＋ 成本上限。
M3 的排程與發布那 7 項（第 10～16 項）**不在 P1 驗收條件裡**，可以往後放——
P1 驗收只要求「生出一則合規貼文」，不要求排得出去。

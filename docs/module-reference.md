# 模組對照表｜問題 · 功能 · 參考資料

**建立日期：2026-08-06**

> 每個模組回答三個問題：**它解決協會的什麼痛？它做哪些事？它靠什麼資料與知識做到？**
> 功能清單的細節見 [`module-functions.md`](./module-functions.md)，這份是它的上一層——為什麼要有這個模組。

---

## 1. 一句話總表

| 模組 | 解決的問題 | Phase |
|---|---|---|
| **M-1 協會腦** | 協會的資料散在年報、官網、某個人的腦袋裡，每個人講的數字都不一樣 | **P1** |
| **M0 守門** | 寫錯數字、字號過期、AI 味太重——這三件事都是發出去之後才發現 | **P1** |
| **M1 健診** | 知道募款不順，但不知道卡在曝光、認同還是轉換，開會沒有共同語言 | P2 |
| **M2 年度規劃** | 年度目標只有一個數字，檔期靠印象排，落後了不知道是哪一段落後 | P3 |
| **M3 內容** | 小編每天面對空白編輯器，沒素材時就開始寫空話——而空話正是 AI 味的來源 | **P1** |
| **M4 廣告文案** | 同一套說法投到疲乏，換角度要重新想，而且改文案容易改出沒查證的數字 | P2 |
| **M5 廣告圖片** | 沒有設計人力，外包一張圖等一週，而且圖上的全名與字號常常漏 | P4 |
| **M6 數據儀表板** | Ad Grants 沒人顧，停權了才知道；理監事會的成效報告每次手工做 | P3 |
| **M7 募款銷售頁** | 專案要一個頁面，外包一次十萬、改一個字等三天 | P4 |

## 2. 各模組

### M-1 協會腦

| | |
|---|---|
| **解決的問題** | 協會的事實散落在年報、官網、某位資深同事的記憶裡。每次要寫東西都得重問一次「我們到底服務多少人」，而年報寫 12,480、官網寫 13,000、秘書長講一萬多——三個數字都對不起來，對外講哪個都心虛。 |
| **不解決** | 不幫你產生新事實。它只管理**已經查證過、有出處**的事實。查不到出處的東西，這裡不收。 |
| **功能** | 五分頁 CRUD（組織身分／勸募許可／事實庫／紅線／品牌語氣）· 批次匯入 JSON · 完成度指示 · 字號到期提醒 · 停用不刪除 |
| **吃什麼資料** | — （它是源頭） |
| **產出到** | `orgs` · `org_permits` · `org_facts` · `org_redlines` · `org_voice` |
| **知識來源** | Skill `npo-org-brain`（新建，P1）· Prompt Pack `m-1_org_brain/v1` |
| **前置** | Skill `brand-positioning-architect`（策略層定調，跟 org-brain 的分工見 `open-questions.md` E13） |
| **外部參考** | 協會年報、官網、主管機關的立案與勸募許可公告、第三方公益平台頁面 |

> 這個模組的成敗決定其他所有模組。事實庫是空的，七個工具的產出都會是一堆 `【請補資料】`。

### M0 合規守門（橫切層，不是獨立頁面）

| | |
|---|---|
| **解決的問題** | NPO 做行銷最怕三件事：小編為了寫得動人順手編了一個沒人查證過的數字；勸募字號過期或誤植還在對外募款；產出一看就是機器寫的，反而傷害信任。**這三件事的共同點是——都是事後才發現，而發現時已經發出去了。** |
| **不解決** | 不判斷內容好不好看。它只判斷**能不能發**。文案品質是生成端的事。 |
| **功能** | 11 關檢查 · 守門報告（可存可回看）· 用語字典維護（`auto`／`warn`／`block` 三種處置） |
| **吃什麼資料** | `org_facts`（G1）· `org_redlines`（G2）· `org_permits`（G3）· 用語字典（G5） |
| **產出到** | `generations.guardrail_report` |
| **知識來源** | Skill `npo-compliance-guard`（新建，P1）· Prompt Pack `m0_guard_semantic/v1`（只有 G2、G6 需要 LLM） |
| **外部參考** | 《公益勸募條例》（勸募許可字號、必要支出上限 15%）· 兩岸用語對照 · AI 生成內容標示慣例 |

**11 關**：

| 關 | 檢查 | 實作 | P1 |
|---|---|---|:--:|
| G1 | 事實核對：數字須在 `org_facts` | 程式 | ● |
| G2 | 紅線比對 | LLM | ○ 見下 |
| G3 | 勸募字號存在且未過期 | 查 DB | |
| G4 | AI 人像標示 | 程式 | |
| G5 | 簡體字與大陸用語 | 程式 | ● |
| G6 | 禁用句型「不是 X 而是 Y」 | LLM | |
| G7 | 進度數字逾 30 天不顯示 | 程式 | |
| G8 | 證言須有 `consent_note` | 程式 | |
| G9 | 換算式數字須有來源 | 查 DB | |
| G10 | 頁面服務數據須來自 `org_facts` | 查 DB | |
| G11 | AI 生成圖須標示 | 程式 | |

> P1 的守門範圍只列 G1／G5，但 P1 驗收條件要求「沒有觸犯紅線」＝需要 G2。
> 這個矛盾還沒拍板，見 `open-questions.md` A1。

### M1 行銷健診

| | |
|---|---|
| **解決的問題** | 協會知道募款不順，但講不出卡在哪一段——是沒人看到（曝光）、看到了不認同（認同）、還是認同了但沒捐（轉換）。三個問題的解法完全不同，但沒有共同語言就開不了會，於是每次檢討都變成「大家再努力一點」。 |
| **不解決** | 不幫你執行改善。它只告訴你**先做哪三件事**。 |
| **功能** | 逆向偵察 · 20 題問卷 · 三段計分 · 缺口排序 · 前三優先動作 · 十二拍檢核 · 報告產出 · 雙導流 CTA |
| **吃什麼資料** | `orgs`（身分）· `org_facts`（報告中引用的數字） |
| **產出到** | `audits` |
| **知識來源** | Skill `npo-fundraising-audit`（既有，需加雙導流）· Prompt Pack `m1_audit/v1` |
| **借用** | M7 的十二拍敘事結構當檢核表——診斷協會現有募款頁缺了哪幾拍 |
| **外部參考** | 曝光×認同×捐款率三段框架 · 第三方公益平台（iGiving／Backme／嘖嘖）的公開專案頁 · Google Ad Grant 申請跡象 |

### M2 年度募款規劃

| | |
|---|---|
| **解決的問題** | 年度目標訂了一個數字，然後就沒有了。檔期靠印象排、管道配比靠感覺，年中發現落後也不知道該補哪一塊——**因為從來沒拆解過，所以無從比對**。 |
| **不解決** | 不保證募得到。它讓落後的時候**看得出是哪一段落後**。 |
| **功能** | 條件輸入 · 分月拆解（非平均分）· 四大檔期配置 · 管道佔比 · 掛勸募許可 · 月度執行清單 · 風險提示 · 進度追蹤 · 季度檢視 |
| **吃什麼資料** | `org_permits`（檔期能不能掛這張字號）· `org_facts`（去年實績） |
| **產出到** | `fundraising_plans` · `campaigns` |
| **知識來源** | Skill `npo-annual-fundraising-plan`（新建）· Prompt Pack `m2_annual_plan/v1` |
| **外部參考** | 台灣捐款季節性：**年底抵稅是全年最大峰**（列舉扣除額）· 春節前 · 定期定額留存率 |

> **這是七個模組裡唯一的「活文件」**——會被反覆回來改，需要版本與修改軌跡。
> 它也是年度顧問服務的數位載體：工作坊線下做，成果存這裡，季度回來檢視。
> `campaigns` 同時被 M3／M4／M5／M7 的產出參照，是整個系統的樞紐。

### M3 社群內容 ★ P1 唯一生成模組

| | |
|---|---|
| **解決的問題** | 小編（通常兼社工兼行政）每天面對一個空白編輯器。手上有素材時寫得出來，沒素材時就開始寫空話——「讓我們一起為孩子的未來努力」這種。**而空話正是 AI 味的來源**，也是最傷信任的東西。 |
| **不解決** | **不代替你有故事。** 「無 seed 不生成」就是這個意思：模板是骨，肉一定要是真的。 |
| **功能** | 選七型 · 填 seed（必填）· A4 週配額 · 生成 · 守門報告 · 編輯 · 重生成／微調 · 內容日曆 · 排程 · 審核流轉 · 推 Metricool · 發布回填 · 內容去重 · 出圖 |
| **吃什麼資料** | 協會腦**全部五塊** |
| **產出到** | `content_items` · `generations` |
| **知識來源** | 七型範式（從 `ad-engine-content-os` 的 NPO 線抽出，**不是 `threads-method-tbca`，那支不存在**）· Prompt Pack `m3_content/v1` |
| **出圖** | Skill `npo-social-card`（配色需變數化，見 `open-questions.md` E3） |
| **外部參考** | Threads／FB／IG 各自的貼文長度與換行慣例 |

**七型與各自的引擎**：

| 代號 | 名稱 | 引擎 | 限制 |
|---|---|---|---|
| A1 | 導流長文＋輪播 | 換名單 | |
| A2 | 圖一句迷因 | 低成本拉新 | |
| A3 | 大字二選一 | 逼留言 | |
| A4 | 工具單 listicle | 乾貨 | **每週上限 1**（AI 味最高） |
| A5 | 素樸實作碎念 | 養信任 | AI 味最低 |
| A6 | 五步驟＋重複節奏 | 講方法 | |
| A7 | 認知反轉大字 | 蹭常識 | |

**禁用句型**：「不是 X 而是 Y」在 A4 以外全部禁止。

### M4 廣告文案

| | |
|---|---|
| **解決的問題** | 同一套說法投久了會疲乏，CTR 掉了要換角度，但換角度等於重新想一次。而且**手改文案時最容易改出沒查證的數字**——因為改的人不是原本查證的人。 |
| **不解決** | 不做投放與預算配置。只產文案。 |
| **功能** | 選角度 · 填真材料 · 多版本生成 · 版本比較 · 守門 · 編輯微調 · 掛 campaign · 存庫可再用 |
| **吃什麼資料** | 協會腦全部五塊 · `campaigns`（P3 之後） |
| **產出到** | `ad_copies` |
| **知識來源** | Prompt Pack `m4_ad_copy/v1`（來源待定，原列 `npo-meta-writer` 但該支品牌寫死，見 `open-questions.md` E2） |
| **借用** | M7 的 **B08 破除迷思** 與 **B12 換算式** 可直接當廣告角度 |
| **外部參考** | Meta 廣告政策（公益類）· Meta 推流三階段（檢索召回／預測排序／競價） |

### M5 廣告圖片

| | |
|---|---|
| **解決的問題** | NPO 幾乎沒有設計人力。找外包一張圖等一週、改一次再等三天，檔期就過了。而且對外募款素材上要放協會全名與勸募字號，**手工做最常漏的就是這兩樣**。 |
| **不解決** | 不做品牌識別設計。只做投放素材。 |
| **功能** | 選六型 · 自動帶入全名／字號／CI 色 · 生成 prompt · Higgsfield 生成（非同步）· AI 人像標示 · 待補圖清單 · 圖庫管理 · 重生成 |
| **吃什麼資料** | `orgs`（全名）· `org_permits`（字號）· `org_voice`（主色輔色、logo、圖庫） |
| **產出到** | `ad_images` |
| **知識來源** | Skill `npo-fundraising-ad-prompt`（既有，可直接複用）· Prompt Pack `m5_ad_image/v1` |
| **外部參考** | Higgsfield API · AI 生成內容標示慣例 |

**六型募款廣告**：創辦人敘事／破疑慮／贈品回禮／小錢大愛／稅務誘因／能見度補位

### M6 廣告數據儀表板

| | |
|---|---|
| **解決的問題** | 兩件事。① **Google Ad Grants 是免費的每月廣告額度，但有嚴格的維持條件**——CTR 連續兩個月低於門檻就停權，而多數協會是停權了才知道。② 理監事會每季要看成效，秘書長每次都手工從幾個後台抄數字做表。 |
| **不解決** | 不代操帳號。只給建議，實際調整回到人工放行。 |
| **功能** | Metricool 串接 · 拉 Google／Meta Ads · 成效總覽 · Ad Grants 合規檢查 · 停權風險警示 · 調整建議 · 月報彙整 · 成效對回內容 |
| **吃什麼資料** | `orgs` · `content_items.published_url`（把成效對回是哪一則貼文） |
| **產出到** | `metric_snapshots` |
| **知識來源** | Skill `npo-adgrants-ops`（新建）· **RSA 文案改寫需要一個 prompt pack，但清單說 M6 無 pack——這條矛盾見 `open-questions.md` E12** |
| **外部參考** | Metricool API · Google Ad Grants 政策（CTR 門檻、單一關鍵字、出價上限、地理定位、轉換追蹤）· Google Ads API |

> ⚠️ Ad Grants 的政策數值（CTR 門檻、出價上限）是**平台規則，會改**。
> 實作時要把門檻做成可設定的常數，並在文件註明查核日期，不要寫死在程式邏輯裡。

### M7 募款銷售頁

| | |
|---|---|
| **解決的問題** | 專案要一個獨立頁面，但協會只有 1shop 後台能貼 HTML。找外包一次十萬起跳，改一個字等三天。**更根本的是——多數 NPO 的募款頁缺了關鍵的敘事段落**，特別是「破除迷思」與「把捐款換算成單位」這兩個最能說服人的設計。 |
| **不解決** | 不做金流。CTA 導到母站的方案區，錢留在 1shop。 |
| **功能** | 選敘事模板 · 區塊化編輯（12 種）· 逐區塊生成文案 · 設計 token 帶入 · 圖片佔位 · 待補圖清單 · 進度條三模式 · 沙箱預覽 · 匯出 HTML 片段 · 方案區設定 |
| **吃什麼資料** | 協會腦全部五塊 · `campaigns` |
| **產出到** | `landing_pages` |
| **知識來源** | Skill `npo-landing-builder`（新建）· Prompt Pack `m7_landing/v1` · 規格見 [`m7-landing-page.md`](./m7-landing-page.md) |
| **外部參考** | 1shop 內嵌 HTML 規格（`#brt-root` 隔離、`all: revert`）· WCAG 無障礙（`prefers-reduced-motion`、`aria-*`、skip-link）· 十二拍募款敘事結構 |

**十二拍敘事結構**（這份規格最值錢的東西，跟疾病無關，換成任何議題都成立）：

```
① 英雄行動  ② 動機轉折  ③ 問題放大  ④ 情境沉浸
⑤ 知識鋪底  ⑥ 困境結構化（含破除迷思）  ⑦ 參與感  ⑧ 組織可信度
⑨ 真人證言  ⑩ 執行者  ⑪ 資金用途  ⑫ 換算與收單
```

**三個不可省的欄位**：困境卡的 `myth`、證言的 `consent_note`、manual 進度條的 `updated_at`。
**進度條禁止自動遞增**——那是假數字，跟整條產品線的賣點直接矛盾。

## 3. 資料流：誰讀誰、誰寫誰

```
                        ┌─────────────────────────────────┐
        M-1 協會腦 ────▶ │  orgs · permits · facts         │
        （寫）           │  redlines · voice               │
                        └───────────┬─────────────────────┘
                                    │ 全部模組都讀
              ┌──────────┬──────────┼──────────┬──────────┐
              ▼          ▼          ▼          ▼          ▼
            M1 健診    M2 規劃    M3 內容    M4 文案    M5 圖 / M7 頁
              │          │          │          │          │
              │          │ 寫 campaigns ◀──────┴──────────┘
              │          │          │      （掛在檔期底下）
              ▼          ▼          ▼
           audits   plans/campaigns  content_items / ad_* / landing_pages
                                    │
                      全部產出 ─────┼────▶ M0 守門 ────▶ generations
                                    │                    （含守門報告與成本）
                                    ▼
                                 投放發布
                                    │
                                    ▼
                              M6 拉數據 ──▶ metric_snapshots
                                    │
                                    └──▶ 回饋給 M1 診斷 / M2 規劃
```

**兩個關鍵節點**：

- **協會腦是唯一的事實源頭**，沒有模組可以繞過它自己編數字
- **守門橫切在所有產出與落庫之間**，沒有旁路，包括除錯用的
